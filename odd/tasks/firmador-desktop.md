# Feature: firmador-desktop

## Objective
A polished desktop app (pywebview + HTML/CSS/JS) to view a PDF, place the signature stamp visually, sign with the Peruvian DNIe through Windows CNG, and validate signed PDFs.

## Problem / Why
Signing currently requires the CLI with hard-coded stamp coordinates (X1, Y1, X2, Y2) and typed file paths. The user wants a full viewer with high-quality design.

## Scope (authorized)
- Reusable signing core extracted from `firma1.py` (stamp position, page selection, stamp text, PAdES).
- A validation module for signed PDFs.
- A pywebview desktop app with an original design. Reusing gob.pe or Firma Perú branding is not allowed.
- PyInstaller packaging to `.exe`.

## Constraints
- Windows only (CNG). The DNIe is a JCOP3 card read through the `ciamd.dll` minidriver. Windows shows the PIN dialog, and the app never handles the PIN.
- Works offline: pdf.js is vendored locally, with no CDN at runtime.
- UI copy is in Spanish, because the project is Spanish and its users are Peruvian.
- `firma1.py` keeps working as a CLI.

## Tasks
- [x] T1 Core: `firma_pdf.py` (options: relative stamp box, pages `todas` or `ultima`, stamp text, PAdES subfilter). `firma1.py` uses it. `dnie_cng.FirmanteCNG` accepts an optional parent HWND for the PIN dialog. Pytest with a simulated signer.
- [x] T2 Validation: `validacion.py` (signer, signing time, integrity, trust via Windows root store, soft-fail revocation). Pytest.
- [x] T3 Desktop app: `app.py` (pywebview js_api) plus `ui/` (HTML/CSS/JS, vendored pdf.js). Viewer with thumbnails and zoom, a draggable and resizable stamp, signing options, a sign flow, and a validate tab.
- [x] T4 Packaging: PyInstaller spec, build script, README usage.
- [x] T5 Stamp styles: two selectable stamp types. "Firma" has the user-supplied logo on the left and text on the right (`Firmado digitalmente por: <CN>` / `Motivo: …` / `Fecha: %Y/%m/%d %H:%M:%S%z`). "Visto bueno" has an original faint check-in-circle background and text at the bottom (`Firmado digitalmente por` / `<CN>` / `Motivo: Doy V° B°` / `Fecha: %d.%m.%Y %H:%M:%S %:z`). Both are sans-serif (Arial embedded when possible), with no border. The motivo is editable per type and is also written as `/Reason`. The UI has a type selector, a logo picker (copied to `%APPDATA%\FirmadorDNIe`) with preview and "Quitar logo", a matching on-page preview, and the last type in `config.json`. The CLI gains `--tipo/--motivo/--logo`. Tests: date formats, `/Reason`, appearance stream, logo XObject present or absent, V°B° on an already-signed PDF, and config round-trip. Visual check with pypdfium2 PNGs.

- [x] T5b Visto bueno with an image on top: the check image sits at the top at full opacity, with the text below it and no overlap (separate areas). The image is user-configurable like the logo: a `imagen_vb` copy in `%APPDATA%\FirmadorDNIe`, a one-time default from `src/Icono circular con marca roja.png` (not bundled; the original is untouched), a UI picker with "Quitar imagen" (Visto bueno only), and a fallback to the vector check. The preview and help text are updated. The CLI gains `--imagen-vb`, and the default V°B° box is re-tuned. Tests: the image XObject is present at opacity 1, the text and image areas do not overlap, the fallback works, and the config round-trip covers `imagen_vb`. Visual check with pypdfium2.

- [x] T6 Batch queue and close document: an X / Ctrl+W "Cerrar documento" control (returns to the empty state, releases the Python document and the byte-opened temp file, removes the queue item; disabled while signing). A queue of PDFs ("Agregar PDFs" multi-select dialog, multi-drop through the path or byte route, dedupe by path, invalid files shown as Error rows) in a "Documentos (N)" sidebar section with status chips, remove, "Vaciar cola", and lazy loading of the clicked row. Shared stamp settings with a per-document override (box and "Página actual", clamped to each file's page count). Outputs next to each original (no overwrite) or in one folder chosen once; byte-opened items ask for one folder. Sequential batch signing in one worker thread with ONE CNG session (`dnie_cng.SesionFirma`: provider and key opened once, HWND set once, counts logged; the PIN is never touched). Progress pushed with `evaluate_js`, cancel between files, PIN-cancel stops (rest Pendiente), wrong PIN / blocked card stops, other errors mark Error and continue. Summary dialog with "Abrir carpeta" and "Firmar más documentos". Tests: queue, 3-file batch with one session, error/continue, PIN cancel, wrong PIN, folder modes, progress order, cancel, close releases temp, already-signed in batch, per-document override.

## Acceptance criteria
- `python app.py` opens the window. A PDF can be opened, the stamp placed, and the PDF signed (the real card signature is verified by the user with the PIN).
- The signed output has 1 signature and stamps on the selected pages at the chosen position.
- The validate tab reports signer, time, and integrity for a signed PDF.
- `pytest` passes.

## Checks
- `python -m pytest -q`
- A simulated end-to-end signing (CNG step mocked) produces a valid structure.
- A manual run of `python app.py` by the user, including the real PIN signing.

## Routing
- T1–T4: delegated to one writer, because the change spans more than 2 non-trivial files (writer trigger).
- T5, T5b: delegated to one writer (firma_pdf.py, app.py, firma1.py, and ui/ are non-trivial files; writer trigger).
- T6: delegated to one writer (dnie_cng.py, app.py, ui/, and tests are non-trivial files; writer trigger). `firma_pdf.py` did not need changes.
- This is not a git repository, so work-unit commits and native review do not apply. Evidence is recorded here instead.
