# Feature: sello-en-pdf-ya-firmado

## Objective
A second (or later) signer of an already-signed PDF gets their stamp exactly like the first signer: on every page with "todas" (each page at its own position) and drawn normally (not translucent) in the panel, while every earlier signature stays valid.

## Problem / Why
`firma_pdf.py` (module docstring lines 25-29, `modo = "solo_campo" if firmas_previas`) stamps only the signature-field page (last page by default) when the PDF already has signatures. The UI then shows the stamp translucent and dashed with «Sin sello en esta página» on every other page (`ui/app.js` ~1146-1148, `paginasConSello` ~983). On 2026-11-18 a second professional signed a document the user had signed; the stamp did not appear where they looked and the panel looked "invalid". The user wants later signers to stamp normally.

## Gate (high-consequence premise)
The premise to prove BEFORE changing behavior: adding a new signature field with one widget per page (as the first signature does) in an incremental revision keeps every earlier signature intact and valid, and pyHanko's difference analysis classifies the revision as an allowed modification (FORM_FILLING or lower, no unauthorized modifications). If the premise fails, do not change behavior; report the evidence instead.

## Scope (authorized, only if the gate passes)
- Signed PDFs (no DocMDP no-changes certification) get the same stamping modes as unsigned ones: "todas" puts a widget on every page at the per-page/document position; the field page keeps its own position.
- UI: stamp opaque on stamped pages for signed PDFs; translucency stays only where truly no stamp will be drawn.
- DocMDP level 1 (no changes) keeps being rejected. Level 2/3 certification: keep current behavior unless the gate proves widgets on other pages are allowed there too.
- Messages and README updated.

## Tasks
- [x] T1 Prove the premise, then enable full stamping on already-signed PDFs + UI opacity + tests (route: delegated writer, trigger: high-consequence assumption + 2+ non-trivial files: firma_pdf.py, ui/app.js, tests).

- [x] T2 Acrobat-compatible stamping: the signature field keeps ONE widget (signature page); every other stamped page gets a locked /Stamp annotation with the same appearance plus a /Link (same rect) whose JavaScript action shows the status of THAT signature (decision change 2026-11-18: no jump to the signature page). Applies to first and later signers. Our validator must not flag these later annotations as unauthorized on non-certified documents (route: delegated writer, trigger: high-consequence + 2+ non-trivial files: firma_pdf.py, validacion.py, tests, README).

### Acrobat evidence that triggered T2 (2026-11-18, user's Acrobat, test certificates)
- Real case: colleague signed with "todas" (one field, 569 widgets) → valid alone; after a second signature (our app) Acrobat shows the FIRST signature «NO ES VÁLIDA – documento se ha modificado». pyHanko said FORM_FILLING/valid: pyHanko and Acrobat disagree.
- A (1st = 569-widget field, 2nd = one page) ✗; B (1st = 569 widgets, 2nd = 569 widgets) ✗; C (1st one page, 2nd one page) ✓ «la revisión no se ha modificado»; D (1st 569 widgets, 2nd one page) ✗; E (like D, each widget with its own appearance XObject and the main widget's keys) ✗.
- F (field with one widget on the signature page; other pages locked /Stamp + /Link GoTo signature page; both signers on every page) ✓ «la revisión cubierta por esta firma no se ha modificado. Sin embargo, se han efectuado cambios posteriores»; clicking a stamp on another page jumps to the last page ✓. pyHanko's default diff policy reported OTHER/docmdp_ok=False for the first signature in F. The F scratch build did not set /Parent on the field's widget; Acrobat listed «Anotación Widget eliminada en la página 569» (the widget is still present in both revisions).
- Conclusion: a signature field with several widgets is incompatible with later signatures in Acrobat (T1's multi-widget approach and sello-clicable-por-pagina are superseded).

## Acceptance criteria
- After a second "todas" signature: two embedded signatures; the first one intact/valid with only allowed modifications; the second intact/valid; each signature field has exactly one widget (signature page) and every other stamped page has one locked /Stamp + one /Link (JavaScript: status of that signature) per signature.
- The panel shows the second signer's stamp opaque on every stamped page.
- Manual check by the user in Acrobat: both signatures «válidas».
